Problem

"What a blend offers under a menu category" has no module; the key set is typed out in 4+ places, the blend page labels categories differently from the menu, and the sweetness remark follows two different rules (sweetnessScale vs key === "latte").

Solution

Put the rules into one module next to lib/seasonal.ts, fed by the matcha and menu-category collections. The landing menu and the blend page both read from it. availableMenuItems and MATCHA_MENU_KEYS become its implementation.

Wins

  • locality: new category key in one place
  • leverage: one interface, two pages
  • labels and sweetness rule stop diverging
  • unmatched category id fails loudly
  • pure data in, rows out: testable

Problem

Problem

A live season links and prices a blend by copying it. Archiving the blend (which changes its id) or hiding it breaks the link and the build stays green.

Solution

Seasons that feature a blend fetch its href (and, if wanted, its live price) through the blend-menu module, which fails on a missing or unavailable blend. Past seasons can keep hand-set prices as a record.

Wins

  • leverage: third caller, same interface
  • broken blend link fails the build
  • live price can't drift

4 · Separate "archived" from the blend id

Speculative in-process
  • src/collection-definitions/matcha.ts (glob **/index.md, generateId: entryId)
  • src/lib/content.ts (entryId)
  • src/content/matcha/archived/2026/*

Before: one path, three meanings

After: folder is storage, flag is state

archived/2026/asatsuyu/index.md
matcha loader archived/ excluded (or id strips it) · one rule, one place
url stable: /matcha/2026/asatsuyu

Problem

Moving a blend to archived/ changes its id and URL but hides nothing. The convention is in no doc, and both 2026/asatsuyu and archived/2026/asatsuyu exist today.

Solution

Pick one meaning for archived/ and put it in the loader: excluded from the collection, or stripped from the id with available derived from it.

Wins

  • locality: archive rule in the loader
  • URLs survive archiving
  • one flag instead of two
